# User Experience and Functionality

MoveOne is a transport planning prototype that presents a connected travel experience for Sri Lanka in 2100. Its user experience guides passengers through destination selection, route comparison, booking and journey tracking. Users can interact through visual controls, typed requests or voice conversations, allowing them to choose an approach that suits their preferences and situation.

The interface uses a consistent dark theme, translucent glass panels, cyan and purple accents, and transport icons. Destination images provide visual context, while prominent buttons identify the next action. Discover, My Journey and Live Map organise the main tasks. Responsive layouts and mobile bottom navigation support use across desktop and smaller screens.

The journey planner allows users to select a starting point and destination, swap them and compare routes. Selectable locations correspond to the eight destinations with dedicated images. Validation prevents identical departure and arrival points. Route cards display estimated duration, fare, transfers and transport modes, helping passengers compare speed, cost, comfort and walking requirements. A detailed timeline explains individual walking and vehicle segments.

Journey AI provides an alternative way to plan a trip. Passengers can make requests such as “Take me to Galle” and refine a recommendation with “Make it cheaper” or “No air taxi”. Conversation context retains the destination and relevant preferences between requests. A prominent microphone, visible voice status and contextual “Try saying…” suggestions introduce the interaction. Suggestions submit requests directly, while typed input remains available when speaking is unsuitable or microphone access is unavailable.

Recommendations appear in a dedicated card that keeps key journey details separate from the conversation history. Users can review the proposed route, request another option and proceed to booking. The booking flow is divided into passenger details, seat selection and payment. Field validation provides feedback before progression. Confirmation produces a digital ticket containing the route, travel date, times, seats, fare, booking reference and QR code, with download and sharing options.

The Live Map demonstrates journey progress through an animated vehicle position, remaining travel time and upcoming stops or transfers. Playback controls allow the simulation to be paused and resumed. Optional spoken guidance uses the same browser voice approach as Journey AI, supporting consistency across both experiences. Ticket access and a cancellation confirmation provide additional control during the journey.

Accessibility features include keyboard-operable controls, descriptive labels, visible focus indicators and announced status updates. Touch-friendly controls and compact mobile layouts support interaction on smaller devices. Voice pause and end controls let users manage the conversation, while text input offers an alternative interaction method. These features support inclusive use, although formal accessibility and usability evaluations are still required.

The current implementation demonstrates the intended experience using simulated routes, fares, vehicle movement, seat availability and payments. Bookings remain within the browser session, and no real transport reservation or payment is processed. Journey AI uses predefined language rules rather than unrestricted language understanding. Future evaluation should test task completion, clarity of feedback and ease of use with representative passengers.
